# Nova-3 classroom performance experiment

**Historical experiment record.** The owner subsequently approved Nova-3 as the normal interview engine; see [current production source status](PRODUCTION_SOURCE_RELEASE_2026-11-13.md). The adult-consented `/?speech-lab` comparison page remains available only in development builds. Its two-session/90-second trial controls are separate from the normal interview. These experimental measurements do not establish a verified accuracy percentage.

## Implementation and boundaries

- The diagnostics enumerate audio inputs after microphone permission, display the active track label where the browser exposes it, and allow an exact device selection for Nova-3. Browser SpeechRecognition chooses its own input. The setup microphone test in `?nova3` now displays **confirmed words**, not only permission status. A user can stop that test before starting the interview.
- The selected microphone is captured as mono with browser echo cancellation and noise suppression. The AudioWorklet converts the actual AudioContext output to signed 16-bit PCM. Native-rate and requested 16 kHz AudioContext modes are available for a measured comparison; the actual context sample rate is sent in the Deepgram URL and displayed. A browser that cannot open 16 kHz reports a capture error instead of falsely labelling its audio. AudioWorklet resampling quality and headset processing require real measurements.
- Nova-3 uses `en-GB` and interim results. The lab compares provider-default, 300 ms and 500 ms endpointing. Paid keyterm prompting is disabled in the bounded live trial. WER details show substitutions, deletions and insertions against the exact words spoken.
- The chosen **provisional design is one WebSocket per question**. Microphone audio is sent only while that question's recording is active. Stopping flushes PCM, sends `Finalize`, waits up to two seconds for a final response, then sends `CloseStream`. Navigation waits for this stop before changing question. Replay stops recognition before starting the existing question MP3. Confirmed words are committed to the answer; provisional words are displayed separately and never committed. Late callbacks are rejected by recording generation, question ID and interview start time. Typing remains available, and “Continue speaking” or “Repeat my answer” offers voice recovery.
- The reusable WebSocket hypothesis remains **unselected**. It would need intentional silent periods, documented KeepAlive traffic and question-boundary isolation tests. With no real Deepgram/network measurements, selecting it as more reliable would be unsupported. The current per-question approach avoids an idle open socket during narration or pauses, at the cost of ten handshakes and token grants per student. Token expiry after a successful connection is not treated as a reason to close the active socket; reconnect obtains a new grant.
- The browser holds the temporary grant; the permanent `DEEPGRAM_API_KEY` stays server-side. Guest cookie, CSRF, same-origin, classroom-open and existing session limits remain required. The server issues at most **3 grants per guest per minute** and **16 per guest per run**. The run allows at most **40 guest sessions**, yielding a hard bound of 640 grants, including retries. The shared 60/minute and 480/run token counters were removed because they bottlenecked simultaneous classes and allowed too few retries. A guest session now atomically reserves one of 40 run slots when the per-IP ceiling equals the run ceiling, avoiding the old shared `guest-total` transaction hot spot. A deliberately lower per-IP limit retains the transactional path; configure limits before opening a fresh run and do not change them mid-run. The slot documents count issued sessions for the whole run and need planned expiry/cleanup after a run.
- No raw audio is written to Firestore, localStorage or the repository. Browser draft answers remain local until the normal submission flow. No AI feedback model or live Firebase data was used in these checks.

The lab has adult-consent gating and exact-reference fields for natural British English, non-native English, continuous speech, pauses, short answers, similar-sounding words and longer responses. Run both engines separately, record the words actually spoken including repetitions, and compare aggregate and per-scenario WER. Target WER ≤10%, preferably 5%, with no material accent or scenario regression; aim for a meaningful improvement over the browser engine. Use wired EarPods, Bluetooth earphones and ordinary headsets. Record first interim/final latency, lost final segments, errors, device name, sample rate and 16 kHz versus native rate. Browser samples/quality must be assessed on the physical devices. Do not label mocked 0% WER as recognition accuracy.

The emulator checks do **not** prove 30 distinct microphone streams, 30 provider WebSockets, p95 latency, school upload bandwidth or actual account allocation. Deepgram's [published Pay-as-you-go rate limits](https://developers.deepgram.com/reference/api-rate-limits) list up to 150 Nova-3 streaming requests on a primary project, but a secondary self-serve project can be limited to one. Confirm the **actual project** allocation and run a consented 30-stream network trial before any classroom recommendation. The app has no hidden queue; network/provider failures retain confirmed answers and typing.

## Trial credit and release gate

The [current promotional price table](https://deepgram.com/pricing) lists Nova-3 monolingual at **$0.0048 per processed minute**. The owner has authorised up to two 90-second live sessions, at most 180 seconds of audio: **approximately $0.0144** at the published rate, below the $0.03 practical target and $2 absolute authorisation. This is an estimate, not observed usage. Thirty students × eight minutes of continuous audio would be **$1.152** base; actual billable audio and contract pricing must be checked in the project. The pricing page also contains an inconsistent per-hour FAQ, so confirm the project quote before spending.

The two bounded audio sessions are authorised and remain **NOT RUN** because only the owner or a consenting adult may speak for this comparison. `/?speech-lab` limits this browser tab to two socket constructions, runs a 90-second hard-stop watchdog, disables reconnection and keyterm prompting, and measures finalisation delay. With `DEEPGRAM_LIVE_TRIAL=true`, the token endpoint fails closed unless `FIRESTORE_EMULATOR_HOST` is set, and its emulator transaction caps the run to two grants. Device inspection does not request a token. The local emulator is ephemeral: restarting it resets its counters. Keep one server process running for both owner trials; browser tab storage also records used sockets across refreshes in that tab. These guards protect the normal owner-operated trial, but are not a cryptographic guarantee against deliberately bypassing the UI or restarting the emulator. Do not use a production Firestore connection for this validation. No Deepgram accuracy trial, OpenRouter request, payment change, production Firebase write, GitHub push, merge or deployment has been performed for this task. Nova-3 remains **NO-GO for merging** until real adult WER, physical iPad Safari, actual-account concurrency and school Wi-Fi measurements pass.

## Current owner-test handoff (13 November 2026)

The original key was placed in tracked `.env.example`; it was moved without printing its value into ignored, permission-restricted `.env.local`, and the tracked example was cleared. That original key could list projects (HTTP 200), but `/v1/auth/grant` returned HTTP 403. Deepgram's [token guide](https://developers.deepgram.com/guides/fundamentals/token-based-authentication) requires Member permissions or higher for a grant, so the old key lacked the permission needed for this flow. The owner replaced it privately with a Member-level key. One deliberate non-audio grant check returned **HTTP 200**, a 30-second token, and no error code. Neither key nor returned token was printed or stored. With the new key, read-only project listing still returned HTTP 200 and balance access returned HTTP 403. Balance access does not block transcription; the owner should inspect remaining promotional credits in the Deepgram Console.

Run `npm run dev:nova3-trial` from the project root, then open **http://localhost:3002/?speech-lab** in Chrome or Safari. The single command starts a local Firestore Enterprise Native emulator for the synthetic `demo-nova3-speech-lab` project and Vercel CLI `dev --local` with real `/api/*` functions. It overrides any production Firebase project/database values from `.env.local` with the demo emulator target, sets `APP_ORIGIN` to the exact local URL, opens a synthetic classroom run, enables the two-grant trial guard, and uses a temporary session pepper if none is configured. It requires Node 24.12+, Java, the cached Firestore emulator JAR and a locally installed or cached Vercel CLI. Stop it with Ctrl-C after both trials. Do not run the old mock preview on port 3002 at the same time. The script fails if either local port is occupied.

The live local API was exercised against the emulator: availability returned `{"open":true}` without a mock marker; a synthetic guest received a secure session cookie and CSRF token; an invalid CSRF request returned 403; two non-audio token grants returned 200, and later grants returned 429. The test emulator was stopped and restarted after this smoke test, leaving **0/2 actual audio streams used** and **0/2 grants used** for the owner's run. No real Deepgram WebSocket was opened by the coding agent. The permanent key stayed server-side. The owner can now consent as an adult, check the intended microphone, enter the exact reference, run Browser SpeechRecognition independently, and use at most two deliberate Nova-3 Starts. Keep this same server running for both tests. Record the exact spoken text including repetitions, both transcripts, WER and latency from the page. The selected input and actual AudioContext sample rate appear in the lab. If the browser rejects microphone permission, typing and previously confirmed words remain available.
